# Agent implementation instructions — ArchTwin

These rules apply to any coding agent (Claude Code, Codex, Cursor, …) and to humans.

## Before writing code
1. Read `README.md`, `docs/PRD.md`, `docs/architecture/SOLUTION_ARCHITECTURE.md`, `docs/architecture/adr/`, `docs/security/THREAT_MODEL.md`, `docs/TECHNOLOGIES.md`, `docs/IMPLEMENTATION_PLAN.md` and `openspec/config.yaml`.
2. Pick **one** change in `openspec/changes/phase-*` and work through its `tasks.md` in order, starting with the `[MVP]` items. Run `openspec validate <change> --strict` before and after edits.

## Rules
1. **Specs are contracts.** Every `Scenario` gets an automated test (positive and negative). Never check a task without merged code and green CI. Never `openspec archive` a phase that is not genuinely shipped.
2. **Modular monolith.** Bounded packages, service interfaces and domain events; no cross-module table access; no new services without an ADR.
3. **Adopt, don't reinvent.** Use the components in `docs/TECHNOLOGIES.md`. Custom infrastructure code needs an ADR.
4. **Security invariants are never optional:** OIDC authentication, Cerbos authorization on every read and write (lists via PlanResources, unknown operators ⇒ deny), project isolation (RequestContext + RLS), audit, secret encryption. Prevent cross-project leakage in search, caches, LLM context, exports and event payloads.
5. **Evidence first.** Every fact carries origin, source revision, observed_at, parser/mapping version and confidence. Missing or stale evidence is UNKNOWN, never absence. Drift is deterministic; LLMs explain and draft only.
6. **AI** goes through LiteLLM only (no provider SDK calls elsewhere), traced in Langfuse. Users choose `gpt-6-luna` (default), `gpt-6-terra` or `gpt-6-sol`, validated server-side. CI uses the fake LLM mode.
7. **Feature flags** for every optional module/provider/AI operation, checked in the API and again when a queued job starts. Core modules and security invariants are not flags.
8. **Connectors are read-only.** External writes require flag + Cerbos `write_external` + preview + approval + idempotency key + audit.
9. **Diagrams** generated by the platform follow the diagram-design system and must pass the diagram linter.
10. **Migrations** are expand → migrate → contract, with N-1 compatibility.
11. Keep OpenAPI, migrations, ADRs, specs, tests and operator docs in sync. No secrets in commits, tests, traces, exports or prompts.
